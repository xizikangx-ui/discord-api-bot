# 荒原档案 · 本地 GM 工作台

1. 将整个 ZIP 解压到任意文件夹。不要在压缩包内直接运行。
2. 双击 `启动GM工作台.vbs`，浏览器自动打开。内附 Windows x64 Node，电脑无须另装 Node。
3. 在 Discord 的跑团服务器使用 `/gm 网页`，复制仅自己可见的绑定码，10 分钟内在网站绑定。每位 GM 使用自己的码。
4. 登录保持 30 天；当前 GM 权限始终由服务器核验。网页「设备与配置」或 `/gm 网页` 可撤销设备。
5. 关闭时点击页头「关闭工作台」。再次双击会重开已有服务。

网页连接当前生产 Bot，修改会影响真实跑团。默认服务地址已填好；本地网页只监听 `127.0.0.1:47831`。

## 常用操作

- 内容录入：选择类型，编辑或复制现有模板，填写表单，预览并发布。「允许生成／发放」取消勾选可停用；修改历史资产不会重写快照。
- 角色与发放：选择角色、项目、数量，加入清单；可复制行、给不同角色设置不同数量，最后统一预览确认。每个角色整笔成功或失败，其他角色仍返回独立结果。常规发放不含杂物。
- 地图管理：选择地图，点格子填写位置，使用下方管理操作；生成随机布局只在正式提交时执行。BOSS 通知和环境 RP 使用已配置 GM 隐藏频道。
- 战斗管理：选择战斗和参战者；位置、血条、异常、装备等编辑通常须先暂停。NPC 实际行动须在其行动机会内；网页不会代替其他玩家行动。
- 内容与公示：正文、概率、开团、鉴定、图片、结果补发与权威存档恢复。补发前须人工核对频道，填写已存在消息 ID 或确认没有送达。
- 图片：先选 NPC 模板与头像／立绘位置，上传 PNG/JPEG/WebP（最多4MiB），再预览确认绑定。上传结果不明确时停止重发，由管理员核对加密图片记录。
- 销卡和判死：填写理由，核对受影响角色后确认；审计和死亡清理沿用 Bot 规则。

## Excel、CSV 与 JSON

`samples` 提供示例。复制 Excel（含标题行）后粘贴即可，也可导入 UTF-8 CSV/JSON。

模板 CSV 用 `templateKind` 指定录入类型，`kind` 表示物品类别。新建用 `baseVersion=0`，不填 ID；修改须填写稳定 `id` 和当前 `baseVersion`。同名内容不会覆盖。

复杂效果可填 JSON；嵌套字段也可用点号，例如 `damage.physical`。每组最多100条，逐行校验，全部通过后整组原子发布。多于100条分组确认。

发放列：`uid,type,ref,quantity`。`uid` 是 Discord 成员ID（按文本存储），`type` 为 item/xp/points/tickets/skill/checkskill/coupon；`ref` 是项目稳定编号。技能数量为1。导入时绑定当下角色编号，角色变化会拒绝提交。

## 草稿与失败处理

编辑会自动加密保存到 Windows 当前用户 `%LOCALAPPDATA%\DiscordRpgGM`；服务器草稿仅本人可见。凭证和草稿采用 Windows DPAPI，复制到其他用户或电脑无法解密。

并发修改会保留填写并展示当前差异，重新核对版本再预览。普通确认有效6分钟，防守不延长原期限。

超时先点「查询已保存结果」。回执确认已提交会展示原结果；处理中继续等待；结果不明确时冻结修改，使用权威存档恢复。不要重新创建同一批发放来绕过未知结果。

页面和启动包不含 Bot Token、数据库地址或 GM 凭证。无需开放本机端口给外网。

连接会采用已设置的HTTP(S)环境代理，或Windows当前用户已启用的系统代理；不会修改Windows代理设置。本机地址始终直接访问。如果你的网络不允许直连Railway，请使用你已有的正常联网配置后再启动。
