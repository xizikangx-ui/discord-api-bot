# NPC 自动与 GM 手动操作

NPC 默认自动操作。系统轮到 NPC 时选择当前合法动作；没有可用操作时正常结束机会。不会为了挑选动作重新掷真实伤害、免费增加弹药或绕过控制异常。

GM 有两处可切换：

1. 内容录入 → NPC → “NPC 操作方式”：选择“自动操作（默认）”或“GM 手动操作”，发布后影响后续生成的实例。
2. 战斗管理 → 选中战斗 → NPC 名单：直接点击“改为 GM 手动”或“恢复自动操作”，只调整当前战斗实例。模板和其他 NPC 不随之改变。

手动选择持久保存，刷新、恢复存档或重启不重置。自动／手动切换从保存后的下一步生效，已经成立的攻击、已保存骰点和待防守结算继续沿用原结果。

自动策略、目标选择及高级权重仍可编辑。默认智能策略；概率策略的每组权重仍须合计 100%。当前 AI 操作异常或超出安全步数时保留原暂停与 GM 处理入口。

## 旧存档兼容

按本次“全部 NPC 先设为自动”的要求，网站每团执行独立的一次性升级 `webNpcAutoVersion=1`。它只调整以下现有对象的 AI 模式：NPC 模板、未结束战斗中的 NPC、房间模板内的 NPC 快照、未结束地图当前与剩余批次 NPC、BOSS 原房间备份中的 NPC。

这次首次切换也包括此前设为手动的对象；安装完成后，GM 新作出的手动选择优先。已结束战斗和地图的历史实例不修改。角色、资产、HP、AP、行动机会、伤害骰点、奖励、布局及怪物数量不重置，不重跑旧内容包或资产迁移。

标记是 PostgreSQL 加密存档的顶层元数据，纳入现有保存、备份和恢复。不能在每次查询或刷新时重新批量设置 AI 模式。此次发布网站；Discord Bot 实例不重启。共用代码对缺省 AI 模式采用自动，明确的 `manual` 仍可正常执行。

## 验证

`test/web-npc-auto-policy.test.js` 覆盖缺省模式、一次性升级、冻结快照、历史保护、手动覆盖、队列执行、已成立结果保护、独立网站范围及 GM 编辑器展示。真实 PostgreSQL 用例验证首次加载持久标记、GM 切为手动、第二个读取器重启后不再次升级。没有测试数据库连接时明确跳过 PG；远程缺少前端依赖时只跳过 SSR，不能称其为浏览器验收。
